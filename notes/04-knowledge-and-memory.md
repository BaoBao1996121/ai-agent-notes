# 04 · 知识、检索与长期记忆怎样分工

> 来源：原教程 Ch06；2026-11-09 公开修订。

“保存了文件”“检索到了片段”“模型在回答时正确使用它”是三个不同结果。知识管理需要分别验证它们。

## 先分清保存的是什么

| 内容 | 合适的记录方式 | 常见错误 |
|---|---|---|
| 项目事实 | 有日期和来源的文档 | 把旧部署状态当作当前状态 |
| 设计决定 | 约束、选择、理由、代价 | 只留下方案，没有为什么 |
| 任务进度 | 已完成、待完成、证据位置 | 把下一步计划写成已完成 |
| 用户偏好 | 用户明确表达及适用范围 | 从单次行为推断永久偏好 |
| 可复用做法 | 触发条件、步骤、验证、限制 | 把一次成功变成强制流程 |

## Markdown 索引与 RAG 可以一起工作

Markdown 是一种材料组织方式；RAG 是检索后辅助生成的方式。它们并不互斥：知识库可以用 Markdown 保存全文，用关键词或向量检索定位，再按章节补读上下文。

选型应看任务，而不是看一个固定页数门槛：

- 经常查精确标识、配置名或错误码，先试关键词检索。
- 用户用多种说法描述同一概念，可以评估向量召回的增益。
- 需要理解长流程，保留章节关系和例外条件，避免只拿孤立片段。
- 材料更新频繁或多人拥有不同访问权，索引更新与权限过滤要一起设计。

这些是待用本地样例验证的设计选择，不是对所有知识库都成立的性能排序。

## 一个最小、可维护的结构

```text
knowledge/
  index.md           # 读者从哪里开始
  concepts/          # 术语和关系
  decisions/         # 选择、理由与适用条件
  procedures/        # 可执行做法
  evidence/          # 验证记录与公开允许的产物
```

每条重要结论至少附上：来源、日期或版本、状态、何时应该重新核对。对私人和工作材料，访问范围要在检索前约束，不能检索后再指望模型“不要说出来”。

## 怎样知道知识库有用

先列出一组真实问题：一个精确查找题、一个跨文档关系题、一个版本冲突题、一个应当回答“不知道”的题。记录命中的来源和最终答案是否满足条件，再决定要不要增加重排、图谱或摘要层。

不要用“收录了多少篇”代替“关键问题能否得到可靠回答”。也不要用“文件已索引”代替“内容已审阅”。

练习：选三篇彼此引用的笔记，给每篇补上日期、适用条件和过时判据。然后故意加入一个旧结论，检查导航能否把读者带到当前权威材料。
